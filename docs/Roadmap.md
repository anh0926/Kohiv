# 1. Introduction

This document defines the product roadmap for Kohiv.

The roadmap describes the planned evolution of Kohiv from its initial MVP into a broader personal experience library platform.

The roadmap focuses on:

* User value
* Product capabilities
* Feature progression
* Future opportunities

Technical implementation details are intentionally excluded.

---

# 2. Product Direction

Kohiv is a **personal experience library** that helps users collect, organize, and revisit meaningful experiences.

The product addresses a common problem:

> "I discover interesting places and activities, but I lose track of them or forget about them."

Kohiv provides one place where users can:

* Save experiences they want to try.
* Find experiences easily later.
* Record experiences they have completed.
* Preserve memories of places they have visited.

# Phase 1 — Experience Library MVP

## Goal

Create a useful personal experience library that allows users to save, organize, and revisit experiences.

## User Value

Users can:

* Create a personal collection of interesting places and activities.
* Quickly save experiences they want to try.
* Easily find saved experiences later.
* Record experiences they have completed.

---

## Features

## User Account

Users can:

* Create an account.
* Access their personal experience collection.
* Manage their own experiences.

---

## Experience Management

Users can:

* Create Experiences.
* View Experience details.
* Edit Experiences.
* Delete Experiences.

---

## Experience Categories

Users organize Experiences using predefined categories.

Initial categories:

* Hiking
* Cycling
* Destination
* Scenic Spot
* Café
* Restaurant
* Camping
* Other

---

## Experience Status

The MVP uses a simplified experience lifecycle:

```text
Discover → Save → Experience → Complete
```

An Experience has one status at a time:

### Wishlist

A place or activity that the user wants to experience in the future.

The user saves an Experience because they are interested in visiting or trying it someday.

### Completed

The user has completed the experience and wants to record that they have experienced it.

Future versions may introduce additional lifecycle states if real user needs require them.

---

## Search and Filtering

Users can:

* Search their experience collection.
* Filter experiences by category.
* Filter experiences by status.

---

## Experience Images

Users can:

* Attach images to an Experience.
* Select one primary cover image.

The MVP supports storing multiple images but does not include advanced image management features such as:

* Albums
* Image ordering
* Image editing
* Advanced image organization

---

## Basic URL Import

Users can:

* Save a source URL when creating an Experience.
* Use available information from supported sources to reduce manual entry.

Imported information must be reviewed by the user before saving.

Users remain responsible for the final information stored in Kohiv.

---

# MVP Success Criteria

The MVP is successful when a user can:

* Create an account.
* Save interesting experiences quickly.
* Find saved experiences through search and filtering.
* Update an experience after completing it.
* Add a cover image to remember the experience.
* Use Kohiv as a personal experience library regularly.

# Phase 3 — Intelligent Experience Assistance

## Goal

Introduce intelligent features that help users manage experiences while keeping users in control.

## User Value

Users spend less time organizing information and more time discovering and experiencing places.

---

## Potential Features

### AI-Assisted Content Understanding

Potential capabilities:

* Understand information from supported sources.
* Summarize content.
* Suggest useful information.

---

### Smart Categorisation

Potential capabilities:

* Suggest appropriate categories.
* Identify experience types from descriptions.

Users review and approve suggestions.

---

### AI Recommendations

Potential capabilities:

* Suggest similar experiences.
* Recommend new places based on interests.
* Help users discover experiences.

---

## Product Principle

AI should assist users rather than replace their decisions.

Users remain responsible for reviewing and approving information.

---

# Phase 4 — Experience Planning and Discovery

## Goal

Help users move from collecting experiences to actively exploring them.

## User Value

Users can transform saved experiences into future adventures.

---

## Potential Features

### Maps

Potential capabilities:

* View experiences geographically.
* See completed locations.
* Explore saved experiences by location.

---

### Trips and Itineraries

Potential capabilities:

* Group experiences into trips.
* Create travel plans.

```text
Japan Trip

- Tokyo Tower
- Mount Fuji
- Kyoto
```

# Roadmap Principles

## Deliver User Value First

Each phase should solve a genuine user problem.

---

## Keep the Product Focused

Future ideas should not delay building a useful MVP.

---

## Design for Growth

Kohiv should support future expansion while keeping the current experience simple.

---

## AI Should Enhance the Experience

AI capabilities should only be introduced when they provide meaningful value to users.

---

# Summary

Kohiv begins as a personal experience library focused on one simple goal:

> Help users save, find, and remember meaningful experiences.

The MVP establishes the foundation by allowing users to collect experiences, manage them easily, and record completed memories.

Future phases will expand Kohiv with intelligent assistance, discovery features, planning capabilities, and additional personal life modules.
