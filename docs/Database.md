# 1. Purpose

This document defines the logical database design for Kohiv.

The database is designed to:

- Support the Experience Library MVP.
- Maintain data integrity.
- Allow future expansion.
- Follow relational database best practices.

---

# 2. Database Principles

The database follows these principles:

- Normalize related data.
- Use foreign keys to maintain relationships.
- Store reference data separately where future changes are expected.
- Keep the MVP simple while supporting future growth.

# 4. Tables

## Experience

| Column | Type | Required |
|---------|------|----------|
| Id | int | Yes |
| UserId | string | Yes |
| CategoryId | int | Yes |
| Title | nvarchar(200) | Yes |
| Description | nvarchar(max) | No |
| Location | nvarchar(300) | No |
| Status | int (Enum) | Yes |
| SourceUrl | nvarchar(500) | No |
| CreatedAt | datetime | Yes |
| UpdatedAt | datetime | Yes |

---

## Category

| Column | Type |
|---------|------|
| Id | int |
| Name | nvarchar(100) |

The MVP uses predefined categories seeded during database creation.

Users cannot create custom categories.

---

## ExperienceImage

| Column | Type |
|---------|------|
| Id | int |
| ExperienceId | int |
| ImageUrl | nvarchar(500) |
| IsCover | bit |
| DisplayOrder | int |

Each Experience may contain multiple images.

Only one image should be marked as the cover image.

# 7. Keys

Primary Keys

- Experience.Id
- Category.Id
- ExperienceImage.Id

Foreign Keys

- Experience.UserId
- Experience.CategoryId
- ExperienceImage.ExperienceId

---

# 8. Indexing Strategy

Indexes include:

- Primary Key indexes (SQL Server)
- Foreign Key indexes (generated by EF Core where appropriate)

Future indexes may be added based on application usage.

---

# 9. Future Expansion

Potential future tables include:

- Trip
- Journal
- Recipe
- HealthRecord
- Tags

The current schema supports future modules without redesigning the Experience model.
